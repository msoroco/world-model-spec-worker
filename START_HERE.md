Read batch.json, UPDATE.md, runtime/stage-contracts.json and skills. Use only this repository. No simulator or upstream project is accessible.
Spawn four subagents, one per partitions/*.json. Only the lead commits/pushes worker/demo-test-preparation-v2. Each owns its work/<assignment-id>/.
Complete ALL six responsibilities: (1) read supplied exact law/cell/actor/witnesses/summaries/existing evidence; (2) explain cases/comparisons; (3) implement road/intersection builders, physical controllers and camera configurations; (4) implement geometry/capture/result checks; (5) run offline CPU tests; (6) deliver executable packages with explicit runtime uncertainties. Plans alone are insufficient.
Use examples for construction, capture, raw observations and output patterns. Inspect the target environment and runtime/python sources. Runtime imports must be lazy so --check works without CARLA. Resolve absent source structures by generating draft templates/bindings from exact law+summary using the supplied stage contracts; lack of human review is not a blocker. Mark real text/summary conflicts. Never fabricate observations, legal thresholds or capabilities.
Each assignment returns case-plan.json, HANDOFF.md and result.json regardless of status. The plan includes assignment_id, actor, cell_id, law_id, cases (globally unique IDs beginning <assignment-id>__), comparisons (case_ids, deliberate_differences, fixed_conditions), observations (name,mandatory), sources (path,sha256), existing_evidence, runtime_uncertainties. Use ready|partial|blocked statuses with exact input_sha256 and applied_update. Partial status never bypasses plan checks.
A ready package includes runner.py, config.json, construction.json with EXACT canonical construction stage keys and inline files matching actual files, proposals/cases.json using the exact cases-stage schema, tests/test*.py, and hashed test logs in result.tests [{command,exit_code,log,sha256}]. Runner accepts --check (offline) and --output-dir PATH --host HOST --port PORT (later live execution). Provide executable capability configurations and explicit measured-results-to-finalization procedure when range/duration depends on physics. Capability-ready is not accepted delivery. Preserve baseline nonselection, unresolved judgments, heavy_vehicle_driver and existing evidence. Restore owned world settings and actors on termination; do not own the simulator server itself.
Run python3 worker_check.py --complete. The lead reviews and reruns each ready runner's --check and assignment unittest suite; record exact commands, exit codes, logs and source hashes. This explicitly authorizes CPU tests, not simulation. Do not claim ready with placeholder code or merely mocked physics.
At startup, between tasks, approximately every 15 minutes and before delivery: fetch origin/main. Commit current edits before merging at a safe checkpoint. Process unseen update JSON notices in order, notify owners, and write work/<assignment-id>/update-acknowledgements.json. Run python3 update_status.py. Continue does not undo a pause: only explicit resume does. Pause-affected blocks those assignments; pause-all blocks all. Conflicts block affected work while independent work continues. Do not reset/force-push or change credentials. A stopped agent processes updates on restart.
Lead validates, commits and pushes the one return branch. If authentication fails preserve commits and report it. Do not launch GPU workloads or claim legal/physical acceptance.

For case-specific configurations, supply additional canonical construction proposals under constructions/<case-id>.json with their own inline config.json. Use identical implementation files within a linked comparison. The root construction.json is the first-case anchor; identify every additional proposal in HANDOFF.md so local adoption requires no schema translation. Do not count missing templates as an unavoidable GPU gap: draft them from the supplied exact summary/text and preserve review status. Run python3 -m unittest discover -s tests, plus all three examples' test suites, before final delivery.
